# Project specialization layer — PetSuite

This directory is **PetSuite's** half of the Kuraka contract.
`kuraka.config.yaml` at the workspace root holds the machine-readable facts
(stack, paths, commands, limits); everything here is the institutional
knowledge that does not fit in a YAML field — the conventions this team
actually follows, the traps in this codebase, and the lessons paid for in
production.

Framework agents (po-analyst, story-refiner, backend-developer,
frontend-developer, code-reviewer, security-reviewer, …) read these files at
invocation time. What is written here is what they will enforce.

## How to read these files

Every convention file follows the same shape:

1. **Context** — what was detected, with a confidence rating.
2. **Rules** — what to do, phrased as *this team does X*.
3. **Examples** — real snippets with `path:line` references.
4. **Anti-patterns detected** — violations that already exist in the codebase.

**The anti-pattern sections are not a work queue and not a review checklist.**
They exist so an agent recognizes an existing pattern as known debt rather than
reporting it as a fresh discovery. Findings must be scoped to the story's diff.

## Three things that will bite an agent that skips this layer

1. **There is effectively no automated safety net.** Zero backend tests against
   ~22,300 LOC; no linter or type checker on either side; `npm test` is
   currently red on stale boilerplate; neither CI workflow runs a test. The only
   gate that can fail meaningfully is `npm run build`. Read
   `gates-and-verification.md` before declaring any phase green.
2. **Tenant isolation is opt-in and mostly opted out** — 4 of 29 models carry
   the global scope, and 23 of 43 controllers query with raw `DB::table()`.
   Read `tenant-isolation.md` before touching a query.
3. **A cross-cutting change is two repos, two commits, two deploys** — and
   adding a module means four coordinated edits. Read
   `workspace-and-deploys.md` before scoping a story.

## Maintaining this layer

- **Amend a convention file in the same cycle that changes the convention.** A
  stale rule here is worse than no rule: agents will enforce it.
- **Add an `LL-NNN` entry after any incident that cost rework.** Reference it
  by ID from the relevant convention file.
- **Resolve `<TODO: confirm with team>` markers rather than deleting them.**
  Each one marks a decision the code could not settle; deleting it silently
  converts an open question into an invented convention.
- Per `.claude/rules/16-agent-backup.md`, mirror changes here to the Obsidian
  vault in the same session.
